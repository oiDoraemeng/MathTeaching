## Context

旧 `LinearAlgebraCase` 模型已移除。新实现将讲义目录、解释内容和确定性 `CommandPlan` 分模块维护，选择主题后由主窗口原子清场并加载，再通过 `math_case` 事件在右侧打开解释页。课程树由 manifest 构建，支持讲义层级、搜索和批量展开状态。

讲义前三章同时包含几何直觉、纯计算、证明推导和练习。本变更只选取直接受益于场景绘图的主题，避免把软件目录变成讲义全文镜像。

## Goals / Non-Goals

**Goals:**

- 用稳定数据字段表示“章 / 节 / 可绘图主题”路径，并由讲义 manifest 驱动树和加载逻辑。
- 让默认、展开全部、折叠到章级和搜索四种目录状态可预测、可测试。
- 在命令白名单内覆盖前三章的核心几何直觉，并提供独立的 2D/3D 教学绘图能力。

**Non-Goals:**

- 不导入讲义全文、练习、自检、严格证明或纯符号计算目录。
- 不增加可编辑主题参数或动画时间轴；三维线段与体积使用确定性静态教学协议。
- 不改变案例标签的瞬态语义、Agent 会话持久化或 Python/React bridge 协议。

## Decisions

### D1. 在案例记录上存储目录路径

`LessonEntry` 保存 `source_path` 和 `SourceAnchor`，固定为章、节、叶子标题。弹窗从 manifest 节点构建树，而不是维护第二份 UI 专用目录。稳定主题 ID、显示路径、解释和绘图引用由注册表统一管理。

替代方案是建立独立目录节点表，但会引入案例 id 到节点的额外映射和漂移风险；当前目录只有三层，不需要通用内容管理系统。

### D2. 只把可加载案例放在叶子节点

章与节节点只负责导航，叶子节点保存主题 id。单击叶子通过 `requested(str)` 信号加载；分支节点保持展开/折叠语义。目录固定包含 54 个主题叶子，覆盖：

- 第1章：向量表示、加减、数乘、线性组合、叉积、内积与夹角、投影、三角形中位线。
- 第2章：矩阵乘向量、复合变换、矩阵与基、秩/零空间/列空间。
- 第3章：有向面积、行列式性质、Cramer 面积比、逆变换、`det=0` 退化。

目录只保留经源文档确认且需要几何表达的主题；自检、练习、挑战和纯符号推导不进入运行时 manifest。

### D3. 搜索过滤整棵树并保留上下文

搜索以不区分大小写的子串匹配主题名称、摘要、公式和完整路径。存在匹配时，仅显示匹配叶子及其祖先并展开匹配路径；清空搜索后恢复默认状态，而不是保留搜索产生的临时展开状态。

“展开全部”展开所有可见目录；“折叠”折叠全部分支，只显示三个章节点。初次打开或清空搜索时展开三个章节点、折叠节节点，因此可见第一、第二级目录。

### D4. 用现有二维原语组合教学图

绘图配方只生成 `CommandPlan`，由 `SceneCommandService` 校验并交给 2D/3D 控制器。通用能力包括投影、角弧、变换网格、子空间区域、有向面积、三维向量、平面和平行六面体；章节配方只组合能力，不直接接触渲染器。

### D5. 保持右侧解释契约不变

`math_case` payload 字段及大小限制不变，主题解释通过同一 JSON-safe 投影发送；source path 只属于课程注册表和 Qt 目录，不跨 bridge 传递。

## Risks / Trade-offs

- [静态案例数量增加使数据文件变长] -> 提取点、向量、线段、标注和通用教学图 helper，按章分段组织，并用目录完整性测试约束。
- [三维对象数量增加渲染复杂度] -> 统一由 `Geometry3DSceneController` 批量管理演员，并在单事务末尾集中 render。
- [搜索过滤可能留下不可见节点的旧状态] -> 过滤时显式设置所有节点可见性，清空时调用统一的默认展开方法。
- [旧测试依赖扁平案例顺序] -> 改为验证 54 个新主题 ID、三章覆盖和每个计划有效，避免对完整显示列表做脆弱快照。

## Migration Plan

1. 先增加目录、解释和配方，保证 54 个计划校验通过且源锚点完整。
2. 再切换弹窗渲染和交互，保持 `requested(str)` 信号不变。
3. 运行 Python 全量测试和 OpenSpec 严格校验；若回滚，只需恢复案例文件与弹窗实现，不涉及持久化数据迁移。
